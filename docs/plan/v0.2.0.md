# CausativeLens v0.2.0：证据闭环更新

v0.2.0 把 v0.1.2 识别出的四个断点收进同一条可复核的证据链：真实 ETW `EVENT_RECORD` 实时消费、SQLite WAL 履约图、性能基线、GUI 双泳道。产品仍保持 `observe` 唯一模式；Jev 只读分析，不修改 Verdict、不启动进程、不执行干预。

## 已交付的工程底座

| 板块 | 实现 | 验证 |
|---|---|---|
| ETW 实时桥 | `clens-capture` 使用 `OpenTraceW` + `ProcessTrace`，每 provider 一个消费线程；回调复制 `EVENT_RECORD` 元数据和用户数据，TDH 读取字段名并按字段读取数值/文本 | `cargo check -p clens-capture --target x86_64-pc-windows-msvc`；Windows 提权机运行 `clens-capture --live` |
| 手工事件 IR | Process/File/Registry/Network 元数据映射、FileObject→Path 驻留、序列分配、bounded channel；队列满时递增 dropped 计数 | capture 单测 + Windows ETW smoke |
| SQLite 履约图 | `SessionStore` 开启 WAL，持久化 assertion、event metadata、evidence、verdict、FTS5；保留 `interventions/decisions` 建表但无写入 | `cargo test -p clens-storage --offline` 的重启重开测试 |
| 离线 why | `session.open_existing` 可重开 `.cllens`，`query.why` 从持久化图读取五段链 | daemon RPC 契约测试 |
| Jev 本地 | `clens-assist` 支持 `local://jev`，从 `CAUSATIVELENS_JEV_COMMAND` 启动本地 runner，stdin/stdout JSON，仍须证据引用 | assistant 单测；CLI 见快速入门 |
| GUI 图 | Canvas 双泳道：断言区、系统事实区、虚拟化窗口、状态与证据连线；颜色遵循 Fluent token | GUI model/browser 测试 |
| 独有算法 | Causal Weave：以 temporal braid、process lineage、contradiction penalty 对相近候选做确定性 tie-break，纯函数可回放 | `causal_weave_is_bounded_monotonic_and_penalizes_contradiction` |

## 真实采集命令

在 Windows 10 Build 10240+、Windows Server 2016+ 的管理员确认窗口中运行：

```powershell
clens-capture.exe --live
```

该命令创建四条 `CausativeLens_*` realtime logger，打开四个 `ProcessTrace` 消费线程，将每条记录转换成 JSON `SysEvent`。结束 logger 会让消费线程退出；队列背压和 ETW loss 必须写入 health。生产 daemon 通过提权 capture host 接收同一 IR；在没有管理员令牌时，状态必须显示 `capture_not_connected`，不能把 harness 日志冒充内核事实。

## 性能基线

使用 Criterion 运行两条可重复基线：

```powershell
cargo bench -p clens-core --bench alignment --offline
cargo bench -p clens-storage --bench spool_decode --offline
```

本机 x64 基线（2026-10-31，release profile）：`alignment/one_candidate` 为 6.22–6.27 ns；`spool/recover_10k_frames` 为 835.38–840.16 µs。Windows ETW runner 另测记录数、TDH fallback 比例、callback dropped、`EventsLost`、`RealTimeBuffersLost`、P50/P99 判定延迟。每次性能 PR 将 Criterion 输出和提交 hash 放在 `dist/bench/`。

## 兼容性

发布目标是 `x86_64-pc-windows-msvc`，静态 CRT；Windows 10 Build 10240、Windows Server 2016 及更新版本是支持基线。`aarch64-pc-windows-msvc` 只在 CI 交叉编译验证，未把 ARM64 二进制伪装成已实测能力。Linux/macOS 只编译业务层，不宣称 ETW 可用。

## 诚实边界

TDH 的字段布局由运行机 manifest 决定，未知事件保留原始元数据并进入 `unknown` 健康计数；没有完整 provider manifest 或管理员令牌时，CausativeLens 输出“证据不可见”，不会输出“未发生”。GUI 与 CLI 的所有结论都来自 daemon RPC 和同一个持久化履约图。
