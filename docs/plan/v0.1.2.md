# CausativeLens v0.1.2 测试版：证据级采集与因果履约方案

语言切换：[English (US)](v0.1.2.en-US.md) · [简体中文](v0.1.2.md) · [繁體中文](v0.1.2_TW.md)。

v0.1.2 仍是 `v1.0.0` 之前的测试版。目标是让产品第一次能够对真实 Windows 会话给出可复核的回答：第 7 步说“只读 `config.yaml`”时，ETW 在同一进程树中看见了什么，结果应标记为履约、偏离、未观测或证据不可见。

## 真实基线

| 承诺 | 当前边界 | 必须补出的证据 |
|---|---|---|
| 内核轨迹 | 需要真实 `EVENT_RECORD`、TDH 对照、rundown、FileObject 路径和时钟锚定 | Windows runner 上的可重放事件包 |
| 数据面 | `.clspool` 帧和恢复逻辑存在；生产 mmap ring/实时桥接仍需复核 | 崩溃恢复、CRC、gap 和吞吐报告 |
| 履约图 | 对齐和查询契约存在；持久化重开必须由测试证明 | `.cllens` 保存/重开及 `why` 证据 |
| GUI | 监听向导和时间线可用；双泳道、虚拟化和真实证据显示需分开测量 | 冷启动、帧率、RSS 和 ETW 证据截图 |

v0.1.2 补证据，不把审计记录改写成完成记录。GUI 的 runtime report 必须和 kernel evidence 分开展示。

## 范围与闸门

只承诺 Windows x64、`observe` 模式和当前用户本机。G0–G7 每个闸门都必须提供测试矩阵、性能数字、已知问题和下一阶段风险；任何缺证据的指标都保持“未测量”。

## 模板与辅助分析

17 家运行时模板继续保留，但不宣称最近三个月每个厂商版本认证。Hermes Agent、Claude Code、OpenAI Codex、OpenClaw、Manus 和 Generic JSONL 优先做真实端到端样本。Jev 以及 OpenAI-compatible、Anthropic-compatible、Ollama 只做证据锚定辅助，不能修改 Verdict、启动进程或执行干预。

## 发布门槛

- 真实 ETW 事件能从 capture 到 daemon 再到履约图，并可回放。
- `mmap ring`、CRC、gap、时钟锚点和 TDH oracle 有可重放证据。
- `clens open` 能重开 `.cllens`；`why` 返回五段式因果链。
- Criterion 有 decode/align/capture-to-query 基线；proptest/fuzz 覆盖顺序、去重和坏帧。
- GUI 显示证据不可见边界，性能数字来自实际测量而不是源码推断。
- Release 资产、SBOM、签名状态和安装器 E2E 报告可追溯。

## 明确不在本方案

干预 `advise/enforce`、Jev 决策后端、跨平台采集器和反事实系统模拟继续顺延。望远镜先校准焦距，再把因果图交给工程师阅读。
