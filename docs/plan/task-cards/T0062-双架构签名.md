# T0062-双架构签名

- 闸门：G7
- 目标：正式包只允许 Azure Trusted Signing 高等级签名；无凭据不得伪造发布签名。
- 实现：`installer/sign-release.ps1`、`installer/generate-sbom.ps1`、`installer/build-installer.ps1`。
- 签名：`signtool sign /fd SHA256 /tr http://timestamp.acs.microsoft.com /td SHA256 /dlib ... /dmdf ...`，随后 `signtool verify /pa /all`；签名状态写入 `dist/signature-status.json`。
- 阻断：Azure DLib/metadata 缺失时只能生成 `unsigned-dev`，`build-installer.ps1 -Release` 必须同时传 `-Signed`；不接受自签名证书作为正式包。
- SBOM：锁定 `Cargo.lock` 的 `cargo metadata` 生成 SPDX 2.3 `dist/causativelens-sbom.spdx.json`。

## DoD

```powershell
powershell -ExecutionPolicy Bypass -File installer/generate-sbom.ps1 -Version 0.1.0
powershell -ExecutionPolicy Bypass -File installer/sign-release.ps1 -Files dist/CausativeLens-setup-x64-dev.exe -AllowDevUnsigned
if ((Get-Content -Raw dist/signature-status.json | ConvertFrom-Json).formal_release_allowed) { throw 'Unsigned local test unexpectedly passed formal gate' }
```

- 证据：`signature-status.json` 与 `payload-signature-status.json`（本机因无 Azure 凭据均为 `unsigned-dev`）、SPDX SBOM、包 SHA-256；正式 gate 返回非零。
- 完成记录：签名和 SBOM 流程已落地；本机正式签名被正确阻断，`build-installer.ps1 -Release -Signed` 没有 payload Trusted Signing 状态时也会阻断。
- 遗留：Azure Trusted Signing account/certificate profile、DLib 与 CI secret 由发布环境注入后才能产生正式签名指纹；ARM64 同样走该流程。
