# CausativeLens v0.1.2 Beta: Evidence-grade capture and causal fulfilment

Language switch: [简体中文](v0.1.2.md) · [English (US)](v0.1.2.en-US.md).

## The promise

v0.1.2 remains a beta release before `v1.0.0`. Its purpose is not another layer of buttons. It is the first release that can answer, from a real Windows session:

> “Step 7 said it would read `config.yaml` read-only. What facts did ETW observe in the same process tree, and do those facts prove fulfilment, deviation, no observation, or an evidence gap?”

The release is therefore **Evidence-grade capture & causal verification Beta**. Without real ETW, TDH parity, cross-process recovery, and a replayable evidence pack, the product must not claim that kernel monitoring is complete. v0.1.1 GUI traces remain useful, but they are runtime reports and must stay visibly separate from kernel evidence.

## One vertical slice

The release targets x64 Windows 10 1809+ / Windows 11, local sessions, and observe-only mode:

```text
choose a Harness directory
  -> standard-user clens-daemon opens a session
  -> only clens-capture elevates and starts four ETW sessions
  -> decode Process/File/Registry/Network EVENT_RECORDs
  -> anchor clocks and reorder QPC events
  -> mmap ring; spill to .clspool without blocking at 95%
  -> tail Harness JSONL and compile Assertions
  -> align by process, time, semantics, and path/endpoint
  -> persist the evidence graph and evidence pack
  -> clens why / GUI Graph renders the five-part causal chain
```

If one station lacks runtime proof, the UI says “not connected” or “indeterminate”; it does not turn a log-only view green.

## Production workflows for technical users

The commands below are target interfaces for v0.1.2. They are not v0.1.1 capabilities and must not be advertised as available today.

```powershell
clens watch --runtime openclaw --trace-dir "$env:USERPROFILE\.openclaw\logs" --path .\case
clens why --session .\case.cllens --path C:\work\config.yaml --json
clens pack --session .\case.cllens --out .\case.causative.zip
clens verify .\case.causative.zip
clens diff .\baseline.causative.zip .\regression.causative.zip --path config.yaml
```

`watch` checks the adapter schema, starts the daemon, requests capture elevation, and reports ETW/JSONL/gap/clock health live. `why` returns the trigger assertion, evidence events, verdict, reverse attribution, and confidence/health. `pack` produces a replayable case without file contents, network payloads, or model secrets by default. `verify` checks CRC, sequence continuity, manifest hashes, and the evidence signature.

## Capture and evidence design

Production capture uses `windows-rs`, not `logman` for session creation. `logman` remains a diagnostic tool. `StartTraceW` creates four realtime sessions; `EnableTraceEx2` applies validated manifest keywords and PID filters; each session has one `ProcessTrace` consumer. A control thread polls loss counters every 500ms. Process/File capture state requests mark rundown facts as `is_rundown=true`; rundown fills state and is not observation-window evidence.

Decoders are keyed by `(provider_guid, event_id, version, opcode, task)`. A cursor layer performs bounded little-endian and UTF-16 reads; a semantic layer maps facts to `SysEvent`; an unknown layer preserves a bounded raw summary and hash. Every manual decoder is compared field by field with `TdhGetEventInformation`/`TdhFormatProperty` output. Failure may fall back to TDH, and the fallback path is recorded.

ETW timestamps remain native QPC ticks. The session adds `clock_domain=qpc_ticks`, `qpc_frequency_hz`, `utc_anchor_100ns`, `anchor_error_100ns`, and `sample_count`; derived UTC is written only when an anchor exists. Sixteen startup samples choose the minimum round-trip pair, followed by a 60-second heartbeat calibration. Drift over `200µs/s` refreshes the anchor and records a `ClockCalibration` fact.

The 256MiB SPSC mapping uses `CreateFileMappingW(..., SEC_COMMIT)` and a named event. The writer commits a CRC-protected frame before publishing its position with Release; the reader consumes with Acquire. At 80% occupancy it warns; at 95% it writes `.clspool` and never blocks the ETW callback. Recovery scans frame boundaries, records corrupt/truncated offsets in `gaps.json`, and deduplicates by `seq`.

## Causal fulfilment that stays honest

Assertions retain the Harness file hash, line/byte span, step, raw quote, extractor version, and process binding. Subject binding starts with the root pid from `run`; shell children use parent pid, time adjacency, and token Jaccard. An unbound subject is explicitly `unknown` and receives no invented attribution.

The compatible `Fulfilment::Unobserved` state gains a visibility qualifier: `complete`, `buffer_loss`, `filtered`, `decoder_unknown`, or `capture_not_connected`. Only `complete` can be read as “not observed”; all other cases are “evidence invisible.”

The CLI and GUI share one RPC result with five sections: trigger assertion; evidence events; verdict and watermark; reverse attribution; capture health. Every event exposes provider, event id/opcode/version, seq, QPC/UTC, pid/tid, decoder path, and rundown status.

## Adapter policy

The 17 requested templates remain. v0.1.2 gives real end-to-end certification priority to Hermes Agent, Claude Code, OpenAI Codex, OpenClaw, Manus, and Generic JSONL. The remaining templates provide path discovery, schema fingerprints, and quarantine for unknown fields; they are not vendor-version certification.

Each watch records an adapter fingerprint: executable version, log root, recent file, schema-key hash, and adapter version. A format change fails the sentinel with “schema changed” while preserving the raw line. A developer can add a fixture without waiting for a binary release.

## Release gates

The release requires the existing Rust checks, four-provider TDH parity, an elevated Windows runner with zero ETW loss, 10,000 controlled events with no sequence holes after kill/restart, five real causal scenarios matching human YAML, and end-to-end verdict latency of P50 ≤ 400ms and P99 ≤ 1.5s. `clens doctor --live-capture` must distinguish capture connected, runtime report, ETW loss, and indeterminate windows.

ARM64 runtime, Linux eBPF, macOS Endpoint Security, remote/WSL/container kernel capture, intervention, the Jev decision backend, content collection, auto-remediation, and cloud upload remain out of scope. Optional evidence explanation through a user-configured Jev-compatible endpoint is covered above; it does not make decisions or enforce policy.

The productivity gain is a shareable, replayable causal object: what the Agent promised, what the process did, why the edge exists, where evidence is missing, and which conclusion must remain humble. A terminal seq, a GUI edge, and a CI regression all point to the same evidence pack.

## Optional Jev / model assistance (already wired, still observe-only)

The workspace now includes `clens-assist`. Both CLI and GUI use it through the daemon's `assist.analyze` RPC. Jev is the default provider label, while the endpoint and model remain user-configured; the client does not invent an unverified service URL. OpenAI-compatible, Anthropic-compatible, and local Ollama providers are also supported.

The assistant consumes only the deterministic causal chain returned by a query. It cannot open a session directory, mutate a `Verdict`, launch a process, or execute advise/enforce/decision. Before sending, paths are replaced with stable hashes and `raw_quote` is removed by default; the prompt is capped at 48 KiB. API keys exist only in the current CLI/GUI process or RPC request and are never persisted. Every finding must cite an assertion id or event seq present in the submitted chain; otherwise the result is marked `grounded: false` with a caveat.

CLI example:

```powershell
clens assist --enable --provider jev --endpoint https://your-jev-endpoint.example/v1/chat/completions --model jev-causal
$env:CAUSATIVELENS_LLM_API_KEY = 'session-only-key'
clens why --path config.yaml --assist
```

The GUI **Settings** page exposes provider, endpoint, model, token/temperature/timeout, path redaction, raw quote, automatic post-query analysis, timeline refresh, and retention controls. The API key field remains in the current GUI process only. Network failures or non-JSON provider output become an explicit ungrounded note rather than a fabricated verdict.
