# CausativeLens v0.2.0: evidence-loop update

v0.2.0 closes the four gaps identified in v0.1.2: live ETW `EVENT_RECORD` consumption, a WAL-backed SQLite fulfilment graph, repeatable performance baselines, and the GUI's dual-lane graph. The product remains observe-only. Jev is read-only assistance: it cannot change a Verdict, start a process, or execute intervention.

## Delivered foundations

| Area | Implementation | Verification |
|---|---|---|
| Live ETW bridge | `clens-capture` uses `OpenTraceW` and `ProcessTrace`, one consumer thread per provider; callbacks copy `EVENT_RECORD` metadata and user bytes, while TDH reads field names and typed numeric/text values | `cargo check -p clens-capture --target x86_64-pc-windows-msvc`; elevated Windows run of `clens-capture --live` |
| Manual event IR | Process/File/Registry/Network metadata mapping, FileObject-to-path interning, sequence allocation, and a bounded channel; a full queue increments an explicit dropped counter | capture unit tests and the Windows ETW smoke run |
| SQLite graph | `SessionStore` enables WAL and persists assertions, event metadata, evidence, and verdicts; `interventions` and `decisions` remain schema-only | `cargo test -p clens-storage --offline`, including reopen-after-close |
| Offline why | `session.open_existing` reopens a `.cllens`; `query.why` reads the five-part chain from the persisted graph | daemon RPC contract tests |
| Local Jev | `local://jev` starts the command in `CAUSATIVELENS_JEV_COMMAND`, exchanges JSON over stdin/stdout, and still requires evidence citations | assistant tests and the CLI guide |
| GUI graph | Canvas dual lanes for assertions and system facts, bounded rendering, status labels, and evidence edges using Fluent tokens | GUI model/browser tests |
| Original algorithm | Causal Weave uses temporal braid, process lineage, and an explicit contradiction penalty as a deterministic tie-breaker | `causal_weave_is_bounded_monotonic_and_penalizes_contradiction` |

## Real capture command

On Windows 10 Build 10240+, Windows Server 2016+, after the administrator consent prompt:

```powershell
clens-capture.exe --live
```

The command creates four `CausativeLens_*` realtime loggers and four `ProcessTrace` consumers, then emits JSON `SysEvent` records. Consumer shutdown follows logger shutdown. Backpressure and ETW loss remain visible in health. An elevated capture host is the daemon integration point; without an administrator token the product reports `capture_not_connected` and never presents harness records as kernel facts.

## Performance baseline

Run the two Criterion baselines:

```powershell
cargo bench -p clens-core --bench alignment --offline
cargo bench -p clens-storage --bench spool_decode --offline
```

The local x64 baseline (2026-10-31, release profile) is 6.22–6.27 ns for `alignment/one_candidate` and 835.38–840.16 µs for `spool/recover_10k_frames`. The Windows runner additionally records event count, TDH fallback ratio, callback drops, `EventsLost`, `RealTimeBuffersLost`, and P50/P99 verdict latency. Performance changes include Criterion output and the commit hash in `dist/bench/`.

## Compatibility

The release target is `x86_64-pc-windows-msvc` with static CRT. Windows 10 Build 10240 and Windows Server 2016 are the support baseline. `aarch64-pc-windows-msvc` is cross-compiled in CI, but ARM64 runtime support is not presented as locally measured. Linux and macOS compile the business layer only; ETW is not claimed there.

## Honest boundary

TDH field layout comes from the provider manifest on the running machine. Unknown events retain raw metadata and are counted as unknown health facts; without a complete provider manifest or administrator token, CausativeLens says “evidence unavailable” rather than “did not happen”. Both GUI and CLI read the same daemon RPC and persisted fulfilment graph.
