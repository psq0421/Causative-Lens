# v0.1.1 Beta：让第一次监听真正开始

此补丁按用户新要求实施，不回填 v0.1.0 闸门通过结论。保持 observe-only、单 daemon 两前端、标准用户权限，ARM64 继续暂缓，测试包未具备正式签名时保留 -dev。

## 用户路径

监听 → 请选择你使用的软件（17 家、WorkBuddy 两渠道、Others，保留 DeepSeek）→ 选择目录 → 自动检测 → 显示识别到的轨迹/范围/限制 → 开始监听 → Timeline。目录可为项目、日志或安装目录；扫描所选目录及用户明确勾选的软件用户日志目录。找不到轨迹给出具体导出提示，可进入等待状态，不能声称已采集系统事件。

Timeline 的全部/断言/文件/网络为真实可点击筛选，支持计数、搜索、暂停跟随、详情、键盘和空态。文件/网络工具轨迹与 ETW 系统证据明确标源，不相互冒充。

## ADR-012

背景：目录本身不提供统一轨迹协议；部分产品仅输出云端结果。决策：模板声明候选目录、扩展名、格式和导出指导；探测内容后选择已有归一器。未知 schema 标记不支持并计数，不能按名称臆造成功。Others 采用同一内容探测链。备选：每家硬编码固定绝对路径，否决因 profile/安装位置/版本不同。

## ADR-013

背景：GUI 应有原生目录选择且保持业务全在 daemon。决策：使用官方 Tauri dialog 插件，仅用于本地文件夹选择；RPC 扫描/解析/提取全部在 daemon/harnessd。不通过 PowerShell/脚本弹出窗口。新增依赖仅 UI 原生对话框，纳入 lock/audit/deny。

## 指标与证据

轮询间隔 500ms；读取线程独立于前端；扫描深度/文件数/单行长度/消息队列有上限且健康报告暴露截断/错误/丢弃。Timeline 数据缓存有界、虚拟行不超过 500，测量 DOM 数与筛选结果；新日志追加后 GUI 显示延迟用 E2E 墙钟记录（测试目标 <3s，不替代完整 ETW 性能预算）。100k 纯数据筛选记录耗时，实际帧率/RSS未测不得写达标。
