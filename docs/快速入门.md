# 快速入门

当前 v0.1.1 可用流程见[新手监听向导](guide/monitoring-start_CN.md)：选软件 → 选目录 → 检测 → 监听 → 筛选/详情/导出。下文保留 v0.1.0 的原接口规划。

> **一次会话，是运行中程序写给未来自己的信；CausativeLens 替你保存信封、时间戳和指纹。**

本指南介绍 Windows 上 v0.1.0 的目标只读观测流程。

> **Beta 现状，核查于 2026-10-25：** `run/attach` 目前返回 `offline`，厂商转换/自动 tail 与完整采集/持久化链路尚未接通；`open` 只创建内存会话，不读取所给文件。下方包括目标接口，不能当作闭环已完成的证明。可验证步骤、厂商日志获取和手工 RPC 接入见 [17 款产品详细教程](guide/runtime-integration_CN.md)。

## 1. 安装

双击对应架构的安装包。安装器会：

1. 让你选择 English、简体中文或繁體中文；
2. 为当前用户安装 GUI、CLI、daemon 和 capture；
3. 幂等写入用户级 PATH；
4. 注册 `.cllens`、HKCU App Paths，以及开始菜单/桌面快捷方式；
5. 检查 WebView2，缺失时引导官方 bootstrapper；
6. 提供“立即重启/稍后”选项，因为 PATH 和 shell 注册需要重启才能让新进程看见。

安装过程不应要求管理员权限。只有实时 ETW 采集需要时，capture 才会触发 UAC。

## 2. 检查安装

```powershell
clens --version
clens doctor
clens doctor --json
```

健康结果会报告 `mode: observe` 与 `installation: installed`。JSON 字段保持英文稳定，方便脚本。

人类文案可以选择语言：

```powershell
clens --lang en-US doctor
clens --lang zh-CN doctor
clens --lang zh-TW doctor
$env:CAUSATIVELENS_LANG = 'en-US'
```

## 3. 实时观测目标接口（本 Beta 尚未接通）

目标嵌入式模式将拉起 Agent 并覆盖完整生命周期。当前命令仅返回 `offline`，不会启动 Agent：

```powershell
clens run -- your-agent.exe --config config.yaml
```

已有进程树的目标接口同样尚未接通：

```powershell
clens attach --pid 12345
```

v0.1.0 的边界是只读。CausativeLens 记录元数据和轨迹，不注入、不修改、不执行干预，也不替 Agent 做决策。

## 4. 查看会话

当前 `watch/timeline` 不按票据选择手工 RPC 会话，`export` 返回 `offline`。空视图不能证明“未发生行为”。

```powershell
clens watch
clens timeline
clens timeline --json
clens export --json
```

也可以使用桌面快捷方式打开 GUI。四个工作区与 CLI 对齐：Sessions（会话与健康度）、Timeline（断言、ETW 事件、水位线）、Graph（证据边与因果断点）、Replay / Query（受限 why、观测结果叠加、JSON 导出）。GUI 不直连引擎 crate，而是和 CLI 一样访问 daemon；两扇窗口可以有不同字体，却必须共享同一份证据。

## 5. 询问 why

查询路由是确定性的，离线可用，并识别中英文：

```powershell
clens why --path config.yaml
clens why "why did it modify config.yaml?"
clens why "为什么它修改了 config.yaml？"
clens why "為什麼它修改了 config.yaml？"
clens why "when did step 12 connect api.example.com:443"
clens why --path config.yaml --json
```

结果固定有五段：触发断言、证据事件、履约判定、反向归因、置信度/健康度。无法识别的自然语言会回退到 `clens why --path <p>`，不会凭空编造查询。

## 6. 可选 Jev / 大模型辅助分析

确定性的五段式因果链始终是事实来源。你可以选择让 Jev 或兼容接口解释这条已经提交的证据链：

```powershell
clens assist --enable --provider jev --endpoint https://your-jev-endpoint.example/v1/chat/completions --model jev-causal
$env:CAUSATIVELENS_LLM_API_KEY = '只在当前终端使用的密钥'
clens why --path config.yaml --assist
```

不希望把密钥放进环境变量时使用 `--api-key-stdin`。密钥永远不会写入 `settings.json`；辅助层只接收有限大小、只读的证据链。路径默认脱敏，`raw_quote` 默认不发送；GUI 的“设置”中可以明确打开。模型引用了证据链中不存在的断言或事件时，会被标为未建立证据关系。

GUI 的“设置”提供同样的 Jev/OpenAI-compatible/Anthropic-compatible/Ollama 选项，以及 token、超时、脱敏、自动分析、时间线刷新和保留条数等客制化项。“查询 → 辅助分析”与 CLI 调用同一个 daemon RPC，不能改变履约判定、执行工具或启用 v0.2.0 干预层。

## 7. 打开与回放

当前 `open` 不读取给定 `.cllens`；已有 replay 比较输入 JSON 数组，不能据此宣称数据库会话恢复已完成。

```powershell
clens open path\to\session.cllens
clens replay --baseline baseline.json --branch branch.json
clens replay --baseline baseline.json --branch branch.json --json
```

v0.1.0 的回放是只读叠加：比较两次观测并高亮差异；反事实模拟属于 v2。

## 8. Harness 日志与适配器

输入约定为 append-only JSONL。通用 parser、tail、quarantine 和 schema 哨兵有库级实现，厂商自动输入尚未接通；运行时描述仍为未验证 Tier3。直接 `session.ingest_harness` RPC 绕过通用 parser，健康计数全零不能证明输入健康。目前没有 `clens adapters doctor` CLI 命令。详见[接入教程](guide/runtime-integration_CN.md)。

## 9. 排查

| 现象 | 操作 |
|---|---|
| 安装后找不到 `clens` | 重启终端或选择安装器“立即重启”，检查用户 PATH。 |
| GUI 显示离线 | 启动 `clens-daemon.exe` 后重试；离线模式仍可打开本地只读界面。 |
| `CL-1001` | GUI/CLI 用标准用户运行，只有 capture 需要 UAC；按错误文案修复。 |
| `CL-2001` | capture 连续三次心跳失联，保留 spool 与健康报告。 |
| 缺少 WebView2 | 运行官方 Evergreen bootstrapper 后重启 GUI。 |
| 卸载有锁定文件 | 重启；卸载器会将文件移入 `.trash` 并重试。 |

powershell -ExecutionPolicy Bypass -File installer/build-payload.ps1 -Arch x64 -Version 0.1.0

## 11. 干净卸载

可以从“设置 > 应用 > 已安装的应用 > CausativeLens”卸载，也可以运行：

```powershell
& "$env:LOCALAPPDATA\causativelens\uninstall.exe" /S /NORESTART /CLEANUSERDATA
```

E2E 闸门会检查文件、注册表、用户 PATH、`.cllens` 关联和快捷方式全部清空。会话数据只有在勾选或传入 `/CLEANUSERDATA` 后才会删除。
