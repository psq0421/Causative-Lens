# CausativeLens v0.2.5：一盏看懂 Agent 的小灯

这几天我们发布了 CausativeLens v0.2.5——这是该项目迄今最大的一次更新。

它做的事情可以用一句大白话说完：**Agent 说“我要做什么”，CausativeLens 再去看“电脑实际上发生了什么”。**

比如，Agent 说：“我只读一下 `config.yaml`。”

CausativeLens 会把这句话变成一条可检查的“承诺”，再去对照系统里看得见的记录：有没有读文件？是不是同一个程序？是不是在合理的时间里？有没有偷偷写入？最后给出“做到了、偏离了、没观察到，还是证据暂时不可见”。

它不会替 Agent 做决定，也不会偷偷修改文件。v0.2.5 仍是 observe-only 测试版。

## 为什么需要它？

我们平时看到 Agent 的回答，像是看一个人写的计划；看到系统日志，像是看监控录像。计划和录像分开时，很难知道“他说的”和“做的”是不是同一件事。

CausativeLens 做的就是把两份记录放到同一条时间线上：

- Agent 的想法和工具调用，变成“因果断言”；
- Windows 的进程、文件、网络等记录，变成“系统事实”；
- 两者对上之后，生成一张能追溯的因果履约图。

所以它不是单纯的日志查看器，也不是传统意义上的杀毒软件。它关心的是：**一个承诺，最后有没有被系统事实兑现。**

## 用起来是什么感觉？

打开 GUI 后，你可以按这样的顺序走：

**会话 → 观测 → 探查 → 回放 → 对比 → 辅助**

先选你使用的 Agent 和它的日志目录。CausativeLens 会尽量识别 Hermes Agent、Claude Code、OpenAI Codex、OpenClaw、Manus 等模板，也提供 Others 通用入口。未知格式不会被假装成兼容成功，而是显示在健康度里。

看到记录后，可以点开时间线里的断言、文件、网络等项目；遇到异常，再进入探查工作区，看断点、证据和前后关系。

如果你问：“它为什么修改了 `config.yaml`？”`why` 查询会按固定的五段格式回答：它当时说了什么、系统发生了什么、判定是什么、这条事件还可能和哪些断言有关，以及当前证据有多可靠。

## 它是怎么保证不乱说的？

CausativeLens 有几个很朴素的原则：

1. 没有看到的事情，就说“未观测到”或“证据不可见”；
2. 日志里的“我写了文件”，不等于操作系统真的写了文件；
3. 模型辅助分析只能解释已经存在的证据，不能凭空创造证据；
4. GUI 和 CLI 使用同一个 daemon，不各自维护一套互相矛盾的结论；
5. 只有采集组件可能请求 UAC，其他组件以普通用户身份运行。

这些原则听起来保守，但调试 Agent 时，保守往往比漂亮的猜测更有价值。

## v0.2.5 更新了什么？

这版把原来比较简单的 Graph + Settings 界面扩展成完整的七个工作区：

- Sessions：查看会话；
- Observe：监听和看实时状态；
- Investigate：找断点和查因果链；
- Replay：回放过程；
- Compare：对比两次观测；
- Assist：让可选的大模型帮你解释已有证据；
- Intervention：未来功能，目前锁定。

还加入了 Windows 风格菜单、快捷键、健康度指示、三种语言，以及更完整的中英繁文档。

## 给普通用户的一句话

如果你正在使用 Agent，CausativeLens 像一个安静的旁观者：不抢方向盘，只把“它说过什么”和“电脑做过什么”放在一起，让你自己看清楚中间有没有走样。

如果你是开发者，它更像一张给 Agent 的体检单：不是只看最后答案好不好，而是看每一步承诺有没有被真实系统行为兑现。

v1.0.0 之前的版本都是 beta/测试版。x64 本机安装、doctor、GUI smoke、卸载和重装已经验证；ARM64、干净 VM、正式签名和完整内核采集矩阵仍会继续单独验收。
